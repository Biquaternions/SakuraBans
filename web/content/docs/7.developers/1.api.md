SakuraBans has a public API in the package `net.serlith.sakurabans.api` (module `api` of the
repository). Compile against the API jar only (`compileOnly`); SakuraBans provides the
implementation at runtime. Declare SakuraBans as a dependency of your plugin so it loads first.

## Getting the API

```java
SakuraBansApi api = SakuraBans.api();           // throws if SakuraBans isn't enabled
Optional<SakuraBansApi> maybe = SakuraBans.find();
```

On Paper it is also registered in the `ServicesManager`.

## What it offers

| Method | Service |
|---|---|
| `apiVersion()` | The API's version (semantic versioning: a new minor only adds). |
| `punishments()` | Punishments: create, revoke, edit, find. |
| `players()` | Accounts, names, addresses and alts. |
| `scopes()` | Scope parsing and resolution. |
| `templates()` | Templates and ladder progress. |
| `allowList()` | The allow list. |
| `events()` | The event bus. Pre-events (present tense, such as `PunishmentCreateEvent`) can be cancelled; post-events (past tense, such as `PunishmentCreatedEvent`) report what happened. Events are posted only on the server where the action happened. |
| `formatter()` | Rendering punishments with the configured messages. |
| `integrations()` | Where other plugins register profile sources. |
| `playerData()` | Exporting and erasing player data. |

Calls that touch the database return `CompletableFuture`s; don't block a server thread on them.
Types you create (requests, scopes) are made with their static `of(...)` or builder methods;
types SakuraBans returns are interfaces. The Javadoc of the `api` module documents every
method.
