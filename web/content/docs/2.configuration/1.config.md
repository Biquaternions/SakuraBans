`config.yml` holds the plugin's behaviour. `/sb reload` applies changes (except
`commands.labels`, which needs a restart); if a value is invalid, the old settings stay active.

`server.name`, `server.categories`, `web.token` and the file-level `geoip` keys can also be
set by the [environment](/docs/configuration/environment) (`SAKURABANS_SERVER_NAME`,
`SAKURABANS_SERVER_CATEGORIES`, `SAKURABANS_WEB_TOKEN`, `SAKURABANS_GEOIP_ENABLED`, ...), which
wins over this file.

Durations use the punishment syntax everywhere: `30s`, `10m`, `1h30m`, `7d`, `2w`, `1mo`
(30 days), `1y` (365 days). Every duration here must be longer than zero, unless a key says
otherwise.

::callout{icon="i-lucide-database" color="info"}
A network may hold **overrides** of most of these keys in the database, per scope: global, a
category or one server (set through the [web editor](/docs/web-editor) or published from a
server's file). For a server, the first layer that sets a key wins: its server scope, its
categories, global, this file, the default. See
[Scopes and layers](/docs/guides/networks#scopes-and-layers).

Keys marked *global only* can only be overridden in global (they must be the same on every
server); keys marked *scoped* can be overridden in any scope; the others are read from this file
only. `/sb settings list [scope]` shows the overrides, `/sb settings reset <key> [scope]`
removes one.
::
## server

| Key | Default | Meaning |
|---|---|---|
| `server.name` | `''` | This server's name, used for server scopes and staff notices: 1-64 characters of a-z, 0-9, `_` and `-`, or empty for none. On a backend, use the name the network knows the server by (its name in `velocity.toml`), so `server:<name>` and category punishments apply here; without it only global punishments and those of `server.categories` apply. On a proxy the name is only the origin of punishments issued there (empty means "proxy"). |
| `server.categories` | `[]` | Categories this server belongs to, so `category:<name>` punishments apply here (backends only). Listing servers under `scopes.categories` is usually simpler, since every backend can share it. |

## scopes

| Key | Default | Meaning |
|---|---|---|
| `scopes.default` | `global` | Where a punishment applies when the command doesn't say: `global`, `local`, `server:<name>` or `category:<name>`. `local` is this server (global while `server.name` is empty); on a proxy it is the server the staff member is on (global from the console). |
| `scopes.require-permissions` *(global only)* | `false` | Whether staff need scope permissions: `sakurabans.scope.global`, `sakurabans.scope.server.<name>` and `sakurabans.scope.category.<name>` to punish or revoke in a scope, and `sakurabans.scope.default` to punish without naming one. |
| `scopes.categories` *(global only)* | `{}` | Categories (groups of servers) and their servers, so `category:<name>` punishments apply on them. On backends keep it the same everywhere. Example: `minigames: [bedwars-1, bedwars-2, skywars]`. |

See [Scopes](/docs/guides/scopes).

## web

The [web editor](/docs/web-editor). These keys are per server.

| Key | Default | Meaning |
|---|---|---|
| `web.url` | `''` | The address of the editor site that `/sb editor` and `/sb applyedits` use, for example `https://editor.example.org`: `https://`, or `http://` for a loopback or private address. Empty turns the editor off; settings, messages and templates still work through the files and commands. |
| `web.token` | `''` | The upload token, if the editor site asks for one. Keep it secret. |
| `web.live-apply` | `true` | Whether a save in the editor applies by itself while its tab stays open, with the permissions of whoever opened it. `false`: every save needs `/sb applyedits <code>`. |

SakuraBans ships with **no default editor address**.

## enforcement

| Key | Default | Meaning |
|---|---|---|
| `enforcement.address-strictness` *(global only)* | `NORMAL` | How far address bans reach through shared addresses: `LENIENT` (that address only), `NORMAL` (accounts that joined from it), `STERN` (one more hop) or `STRICT` (player bans also cover all of the player's addresses). See [Alts](/docs/guides/alts). |
| `enforcement.composite-by-default` *(scoped)* | `false` | Whether `/ban` also bans the player's current address unless told otherwise. |
| `enforcement.mute-command-blacklist` *(scoped)* | `me`, `say`, `tell`, `msg`, `w`, `whisper`, `r`, `reply`, `mail` | Commands a muted player can't use, without the slash. An entry also matches the command under any plugin's namespace (`msg` blocks `essentials:msg` and `minecraft:msg`), so the default list needs no `minecraft:` entries (lists that have them still work). `*` matches any text: `'*:me'` blocks every namespaced `me`, `'minecraft:*'` every vanilla command, `'e*'` every command starting with `e`; quote an entry that starts with `*`. An entry with a colon is matched against the whole label. Matching uses the list compiled when the settings load, so it costs nothing per message. Aliases are not resolved: list every label you want blocked. |
| `enforcement.kick-ignored-reasons` *(scoped)* | `restarting`, `afk` | Kick reasons that leave no record: `/kick` with a reason containing one of these texts (any case) disconnects the player but stores nothing, tells no staff and posts no webhook, like `/kick --no-record`. `[]` records every kick. Only the command is affected; the API always records a kick. |
| `enforcement.enforce-server-switch` | `true` | On a proxy, whether server scopes are checked when a player switches servers. |
| `enforcement.login-check-timeout` | `5s` | How long a join or server switch may wait for the ban check (at most 30s). If the check takes longer or fails (for example the database is down), the player is turned away. |
| `enforcement.servers-without-login-check` *(global only)* | `[]` | **Proxy.** Servers a banned player may still join (a lobby, limbo or appeal server). A banned player gets into the network but only onto these servers; they are told they are banned when they join, and staff aren't told of the join. When a ban is enforced on an online player, the proxy sends them to the first of these servers (in the listed order) that connects, then to its own fallback servers where the ban doesn't apply; if none connects they are disconnected. A player already on one of them stays and is told. Mutes still apply there, and lockdowns still close them. A non-empty list checks every server switch, whatever `enforce-server-switch` says. Ignored on a backend. |
| `enforcement.login-check` | `true` | **Backend.** `false` lets banned players join this server (for example a lobby behind a proxy, with SakuraBans on the backends); they are told they are banned, a ban enforced while they are here doesn't kick them, and mutes still apply. Set per server. Ignored on a proxy. |
| `enforcement.ip-ban-decay` *(global only)* | `never` | After how long a ban of a player *and* an address (`/ban --ip`, or `composite-by-default`) stops reaching through the address and bans the player only: a duration or `never`. Decided by the ban's age whenever it is checked (logins, server switches, live enforcement, `/checkban`, history "applicable to", lists), so nothing is rewritten and changing it takes effect at once, both ways. Plain address bans, ranges and mutes are never affected. `/checkban`, `/sb info` and the lists mark a ban whose address part has decayed. |
| `enforcement.network-kick` *(scoped)* | `false` | **Backend behind a proxy.** `true`: a ban enforced on an online player disconnects them from the whole network, through the BungeeCord plugin channel (see [Networks](/docs/guides/networks)). `false` kicks them from this server only, so the proxy moves them to its fallback server. Bans only; `/kick` always kicks from this server. Ignored on a proxy. |

## alts

| Key | Default | Meaning |
|---|---|---|
| `alts.register-on-connection` *(global only)* | `true` | Whether names and addresses are recorded when players join. |
| `alts.servers-without-ip-registration` *(global only)* | `[auth, limbo]` | Servers that never record addresses (login or limbo servers behind a proxy). |
| `alts.record-expiration` *(global only)* | `never` | How long recorded addresses count for alt detection: a duration, or `never`. |
| `alts.join-notification.enabled` *(scoped)* | `true` | Whether staff with `sakurabans.alts.notify` hear about a joining player's alts, at the configured address strictness. At most once per player per 30 minutes. |
| `alts.join-notification.only-if-punished` *(scoped)* | `true` | Only when one of the alts has an active punishment. |
| `alts.join-notification.threshold` *(scoped)* | `2` | The fewest alts that trigger a notice. |
| `alts.join-notification.limit` *(scoped)* | `20` | The most alts listed in one notice. |
| `alts.auto-ban` *(global only)* | `DISABLED` | Automatic alt bans. `ON_BAN`: a ban of a player (a command or the API) also bans the accounts `/alts` lists for them (at `address-strictness`, within `record-expiration`), except allow-listed, hidden and exempt ones and those already banned in that scope: same reason, scope and expiry, by the same operator, with the source `auto`. Staff get one notice for them all. `ON_JOIN` also bans an account that joins while an address or composite ban reaches it, with that ban's reason, scope and expiry (after `ip-ban-decay`). Nothing happens until the console runs `/sb accept alts` once; the startup log and `/sb status` remind you until then. An automatic ban never starts another round, and revoking the first ban doesn't lift them: use `/staffrollback`. LiteBans' third level is not offered. |
| `alts.auto-ban-confirm-above` *(global only)* | `5` | A `/ban` that would also ban more linked accounts than this needs `--confirm`. The API never asks. |
| `alts.hidden-players` *(global only)* | `[]` | Accounts and addresses that `/alts`, `/ipreport` and the join notification never list: player names, UUIDs, addresses or ranges (`10.0.0.0/8`, `10.0.*.*`). An alt linked only through hidden addresses isn't listed either, and a hidden player who joins tells nobody about their alts. Staff with `sakurabans.alts.viewhidden`, and the console, see everything. Detection and punishments are not affected. |

## reasons

| Key | Default | Meaning |
|---|---|---|
| `reasons.default` *(scoped)* | `No reason specified` | The reason used when none is given (at most 1024 characters). |
| `reasons.require.ban`, `.mute`, `.warn`, `.kick` *(scoped)* | `false` | Whether that punishment needs a reason. |
| `reasons.require.revoke` *(scoped)* | `false` | Whether revocations (unban, unmute, unwarn) need a reason. |
| `reasons.allow-newlines` *(scoped)* | `false` | Whether reasons may contain line breaks. |
| `reasons.shortcuts` *(scoped)* | `{}` | Reason shortcuts: with `griefing: Griefing`, `/ban Steve --template griefing` uses "Griefing" as the reason (a reason given with `-r` is added after it). A template with the same name wins. Names are 1-64 characters of a-z, 0-9, `_` and `-`; a reason is 1-1024 characters. |

## exemption

| Key | Default | Meaning |
|---|---|---|
| `exemption.provider` *(global only)* | `PERMISSION` | Who can't be punished: `NONE`, `PERMISSION` (players with `sakurabans.<type>.exempt`) or `LUCKPERMS_WEIGHT` (staff can't punish someone with a higher group weight; needs LuckPerms). |
| `exemption.permit-same-weight` *(global only)* | `true` | With `LUCKPERMS_WEIGHT`: whether staff may punish someone with the same weight. |
| `exemption.protects-edits` *(global only)* | `true` | Whether exemption also protects punishments from being edited or revoked by lower staff. |
| `exemption.players` *(global only)* | `[]` | Players who can't be punished, whatever the provider says (even `NONE`): a name or UUID, optionally with a type (`Steve:mute`, `<uuid>:ban`) to exempt them from that type only. A name matches only while this server knows the player's name (online, or looked up since the start); an unknown name matches nobody until then, so prefer UUIDs. |
| `exemption.groups` *(global only)* | `[]` | LuckPerms groups whose members can't be punished, checked as the `group.<name>` permission (offline players need LuckPerms). |

`sakurabans.<type>.exempt.bypass` lets a staff member punish exempt players.

## warnings

| Key | Default | Meaning |
|---|---|---|
| `warnings.expire-after` *(scoped)* | `30d` | How long a warning stays active: a duration, or `never`. |
| `warnings.actions` *(scoped)* | `{}` | Console commands run when a player reaches a number of active warnings (in every scope), on the server that issued the warning that reached it. Keys are numbers of warnings (1 or more); each runs when the count is exactly that number. |

Placeholders in warning actions: `{victim}` (the name), `{uuid}`, `{address}`, `{id}` (the
warning), `{operator}`, `{reason}`, `{duration}` and `{count}`. Quote the commands, because YAML
reads `{...}` as a section:

```yaml
warnings:
  actions:
    3: ["tempmute {victim} 1h Three active warnings"]
    5: ["tempban {victim} 1d Five active warnings"]
```

## display

| Key | Default | Meaning |
|---|---|---|
| `display.default-locale` *(scoped)* | `en_US` | The language for messages when the player's own isn't known (for example ban screens). |
| `display.date-format` *(scoped)* | `dd MMM yyyy HH:mm` | How dates are shown, as a `java.time` pattern. |
| `display.timezone` *(scoped)* | `default` | The time zone for dates: `default` (the server's), `UTC`, `Europe/Berlin`, ... |
| `display.id-style` *(global only)* | `NUMERIC` | How punishment ids are shown: `NUMERIC`, `SCRAMBLED` or `BOTH`. |
| `display.censor-ip-addresses` *(scoped)* | `false` | Whether addresses are shown as `203.0.*.*` to staff without `sakurabans.viewips`. |

## lockdown, notifications, players

| Key | Default | Meaning |
|---|---|---|
| `lockdown.persist` *(global only)* | `true` | Whether an active lockdown survives a restart. |
| `notifications.attempt-throttle` *(scoped)* | `30s` | The shortest time between two "tried to join while banned" (or turned away by the [GeoIP](/docs/guides/geoip) country lists; both share it) or "tried to chat while muted" notices about the same player. `0s` turns the throttle off. |
| `players.remote-lookup` | `true` | Whether a name SakuraBans has never seen (for example `/ban` on someone who never joined) is looked up through the server's profile service, which asks Mojang. Turn it off on shared hosting, where every server on the address shares Mojang's rate limit. A proxy never looks names up. |

## audit

| Key | Default | Meaning |
|---|---|---|
| `audit.retention` *(global only)* | `never` | How long audit entries are kept (`/sb audit`): a duration such as `365d`, or `never`. The server that holds the sweeper's lease deletes older entries in batches of 1,000, about once an hour, and logs one line with how many went. Entries are stamped with the writing server's clock, so the cutoff is that server's clock too. Deleting isn't audited entry by entry. The entries of a punishment (`/sb info`) go with the rest. |

## placeholders

| Key | Default | Meaning |
|---|---|---|
| `placeholders.refresh` *(global only)* | `2m` | How often each server reads the network's punishment counts again: the `<total_*>` and `<active_*>` message tags and the `sakurabans_total_*` / `sakurabans_active_*` placeholders. At least `30s`. Until the first read after a start they are empty. A player's own counts are read when they join and when one of their punishments changes, not on this interval. See [Placeholders](/docs/reference/placeholders). |

## geoip

Country lookups and country lists at login; off by default. See [GeoIP](/docs/guides/geoip).

| Key | Default | Meaning |
|---|---|---|
| `geoip.enabled` | `false` | Whether this server loads a GeoLite2-Country database (`geoip/GeoLite2-Country.mmdb` in the plugin folder) for the lists below, `/geoip` and `<country>`. Each server that turns it on keeps its own copy. Needs a restart. |
| `geoip.account-id` | `''` | Your MaxMind account ID, with which this server downloads the database and keeps it current. *Secret.* |
| `geoip.license-key` | `''` | One of that account's licence keys. *Secret.* Set both or neither; with neither, the file is placed by hand and no request is made. |
| `geoip.refresh` | `7d` | How often MaxMind is asked whether there is a newer database: at least `1d`, or `never` (a database is then only downloaded when there is none). Asking doesn't count against MaxMind's daily download limit. |
| `geoip.blacklist` *(global only)* | `[]` | ISO 3166-1 alpha-2 codes (`[CN, RU]`) whose players can't join. |
| `geoip.whitelist` *(global only)* | `[]` | When not empty, only these codes can join; the blacklist is then ignored (a warning says so). |
| `geoip.allow-unknown` *(global only)* | `true` | Whether a player whose country isn't known may join while a list is set: a local or private address, one the database doesn't list, or no database yet. |

## commands

`commands.labels` sets the labels of each command: the first is its name, the rest are aliases
(1-32 characters of a-z, 0-9, `_` and `-`). A command left out uses its own name, except that
`/alts` also answers to `/dupeip` and `/warns` to `/warnings` (LiteBans' names); list a command
to replace its labels. An empty list (`[]`) disables it. Changes need a restart.

```yaml
commands:
  labels:
    sakurabans: [sakurabans, sb]
    unban: [unban, ub]
```

The commands are `sakurabans`, `ban`, `tempban`, `ipban`, `mute`, `tempmute`, `ipmute`, `warn`,
`kick`, `unban`, `pardon`, `unmute`, `unwarn`, `checkban`, `checkmute`, `checkwarn`, `history`,
`staffhistory`, `warns`, `banlist`, `mutelist`, `warnlist`, `alts`, `iphistory`, `namehistory`,
`lastuuid`, `ipreport`, `geoip`, `lockdown`, `staffrollback` and `prunehistory`. The `/sb` subcommands
(including `reset` and `addlogin`) follow the `sakurabans` labels.
