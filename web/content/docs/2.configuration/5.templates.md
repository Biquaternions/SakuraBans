Templates live in the **database** and are shared by every server on it. `templates.yml` only
**seeds** them: it is imported once, on the first start with an empty template table. After
that:

- change templates in game, through the API or in the [web editor](/docs/web-editor), or
- edit the file and run `/sb templates import`, which creates or updates every template listed
  and keeps the others;
- `/sb templates export` writes the current templates to `exports/templates-<time>.yml` in the
  same format.

Both take a scope (`/sb templates import server:skywars` reads only that scope's
[variants](#variants)) or `--all` (every section); with neither they mean the global
templates. The first start imports everything.

How templates behave is explained in [Templates and ladders](/docs/guides/templates).

## Two shapes

A template's `type` decides its shape:

- **Presets** (`type: ban`, `mute`, `warn` or `kick`) fill in one punishment of that type.
  Use them with `-t` on the command of their type: `/ban Steve -t hacking`.
- **Ladders** (`type: ladder`) escalate: each use goes one step further, and each step names
  its own type, or `none`. Apply them with `/punish Steve misconduct`.

Names are unique across both shapes.

## Keys of every template

`type` and `reason` are required; everything else is optional.

| Key | Meaning |
|---|---|
| `type` | `ban`, `mute`, `warn`, `kick` (a preset) or `ladder`. |
| `reason` | The reason when the command gives none. A reason given with `-r` replaces it. |
| `ip` | `true`: punish the player's current address instead of the player, like `/ipban` and `/ipmute`. |
| `shadow` | `true`: its mutes are shadow mutes; the muted player's messages are shown to them only. On a mute preset, or a ladder with a mute step. |
| `scope` | Where the punishment applies when the command names no scope: `global`, `server:<name>` or `category:<name>`. Left out: `scopes.default`. A scope given with the command wins. This is not where the definition is in force (see [Variants](#variants)). |
| `permission-required` | `true`: using it needs `sakurabans.template.<name>`, and so does revoking, editing, voiding, deleting or overriding (`-o`, `--if-longer`) a punishment made from it, from a command or the API. The console always may; a player who is offline is checked through LuckPerms. Once the template (its variant and its global definition) is deleted, its punishments are guarded no more. `/staffrollback` is not affected. |
| `actions` | Console commands run every time the template is used (at most 16, one line each, at most 255 characters). |
| `groups` | `group: weight` (at most 16 groups, weights 1-100). Templates in a group share progress: every use of a group mate, a preset's too, counts as its weight on the ladders of the group (uses whose punishment was voided never count). |
| `message` | What the punished player is shown, instead of the network's message for the type (the ban or kick screen, the mute notice in chat, the warning), in MiniMessage with that message's placeholders. One text for every locale. |
| `silent` | `true`: its punishments are silent, as with `-s` (only staff who may see silent punishments are told; webhooks follow `include-silent`). A command with `--hide` or `--quiet`, or an API call with that visibility, hides them further. Revoking them is not affected. Left out: `false`. |
| `display` | `chat` (the default) or `dialog`: how the mute notice and the warning reach a player who is online. On a mute or warn preset (not a shadow mute), or a ladder with a mute or warn step, where it covers those steps. See [Dialogs](#dialogs). |

## Presets only

| Key | Meaning |
|---|---|
| `duration` | `7d`, `30m`, `1mo`, ... (whole seconds, at least `1s`) or `permanent`. Left out: the command decides (its `-d`, else permanent; a warning gets `warnings.expire-after`). A preset with its own duration refuses `-d` and isn't offered on `/tempban` and `/tempmute`. A kick has none. |

## Ladders only

| Key | Meaning |
|---|---|
| `steps` | The steps (1-64). The first use is the first step, the next use the second, and so on; after the last step it repeats. A step is a text, or a map with that text as `step` (see below). |
| `expiry` | Earlier uses older than this don't count (`none` = all count). Whole seconds, like every duration in a template. |
| `address-shared` | `true`: uses on the player's alts and addresses count too. |

A step's text:

| Text | Step |
|---|---|
| `none` | No punishment: only the actions run. Needs at least one action, and has no message. |
| `kick` | A kick. |
| `warn` | A warning that lasts `warnings.expire-after`. |
| `warn 30d`, `mute 1h`, `ban 7d` | That type for that long. |
| `ban permanent`, `mute permanent` | Permanent. A ban or mute step always names a duration or `permanent`. |

A step written as a map can have its own `reason` and `message` (they win over the template's)
and `actions` (run after the template's):

```yaml
steps:
  - warn
  - {step: ban 7d, message: "<red>Last chance.</red>"}
  - {step: none, actions: ["say {victim} is on probation"]}
```

The keys of the format before typed templates (`ladder`, `ladder-expiry`, `step-actions`,
`step-messages`) are no longer read: a template that uses them isn't imported, and the error
names the new key.

Names of templates and groups are 1-64 characters of a-z, 0-9, `_` and `-`.

Actions may use `{victim}`, `{uuid}`, `{address}`, `{id}`, `{operator}`, `{reason}`,
`{template}`, `{step}` and `{duration}` (`{id}` and `{duration}` are empty on a step without a
punishment, `{step}` on a preset). Quote them, because YAML reads `{...}` as a section.

## Dialogs

With `display: dialog`, the "you were muted" notice and the "you were warned" message open as a
dialog: the template's `message`, or else the network's dialog text (`dialog.muted`,
`dialog.muted_temporary` or `dialog.warned`: the exclamation-mark banner with the lines below
it), with a title (`dialog.muted_title` or `dialog.warned_title` in the language file) and a
close button (`dialog.close`). Ban and kick screens are disconnect screens and stay as they are.
Where no dialog can be shown, the chat message is sent instead (the template's `message`, or the
network's `victim.*` message: the banner with the text beside it):

- on Paper, through Paper's dialog API, always available on 26.3;
- on Velocity, only with the [packetevents](https://modrinth.com/plugin/packetevents) plugin
  installed on the proxy, and only to clients on 1.21.6 or newer that aren't switching servers.

Some messages stay chat on purpose: the line a muted player gets each time their chat or a
blocked command is refused (a dialog on every attempt would be in the way), and warnings shown
at the next join (several can arrive at once, and a dialog replaces the one before it).

## Variants

A template can be defined differently for a server or a category, for example a longer spam
mute on a minigame, under a `variants` section at the end of the file:

```yaml
variants:
  server:skywars:
    spam:
      type: mute
      reason: Spamming in Skywars
      duration: 1d
  category:lifesteal:
    misconduct:
      type: ladder
      reason: Repeated misconduct
      steps: [warn, mute 1d, ban 3d]
```

- A variant is a **whole definition** (nothing is merged with the global one) of a template
  that exists under `templates`, of the **same type**. It has no `groups`: it counts in the
  global template's groups, and a ladder's progress is shared by name, whichever definition
  each use got.
- It is **in force where it is used**, which isn't the same as its `scope` key (where its
  punishments apply). A use gets the variant of the scope its command names (`--server`,
  `--category`, `--scope`; `-g` means the global definition); else, on a backend, this server;
  on a proxy, the server the staff member is on; else (the proxy console) the global
  definition. From a server: its own variant, else its categories' in the order
  `scopes.categories` declares them, else the global one.
- A punishment remembers the variant it came from: every server shows its message from that
  variant, or from the global template once the variant is deleted.
- Deleting a global template deletes its variants.

See [Templates and ladders](/docs/guides/templates#variants) for an example network.

## Example

```yaml
templates:
  hacking:
    type: ban
    reason: Unfair advantage (hacked client)
    duration: 30d
    groups:
      cheating: 2

  spam:
    type: mute
    reason: Spamming
    duration: 1h
    shadow: true
    actions: ["say {victim} was muted for {duration}"]

  advertising:
    type: mute
    reason: Advertising
    display: dialog

  misconduct:
    type: ladder
    reason: Repeated misconduct
    steps:
      - warn
      - kick
      - mute 1d
      - {step: none, actions: ["say {victim} is on a final warning"]}
      - ban 7d
      - {step: ban permanent, message: "<red>Permanently banned for repeated misconduct.</red>"}
    expiry: 90d
```

`advertising` leaves the duration to the command: `/mute Steve -t advertising` is permanent,
`/tempmute Steve 1d -t advertising` lasts a day. Its mute notice opens as a dialog.
