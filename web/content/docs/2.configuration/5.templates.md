Templates live in the **database** and are shared by every server on it. `templates.yml` only
**seeds** them: it is imported once, on the first start with an empty template table. After
that:

- change templates in game, through the API or in the [web editor](/docs/web-editor), or
- edit the file and run `/sb templates import`, which creates or updates every template listed
  and keeps the others;
- `/sb templates export` writes the current templates to `exports/templates-<time>.yml` in the
  same format.

How templates behave is explained in [Templates and ladders](/docs/guides/templates).

## Keys of a template

All but `type`, `reason` and `ladder` are optional.

| Key | Meaning |
|---|---|
| `type` | `ban`, `mute`, `warn` or `kick`: the type of every step that doesn't name its own. |
| `reason` | The reason when the command gives none. |
| `ladder` | One entry per step: a duration (`30m`, `7d`, `1mo`, ...) or `permanent` for the template's type, or a type followed by a duration where the type has one (`kick`, `mute 1h`, `ban 7d`, `ban permanent`). The first punishment from the template uses the first step, the next one the second, and so on; after the last step it repeats. A kick has no duration (`permanent` in a kick template). 1-64 steps. |
| `ip` | `true`: punish the player's current address instead of the player, like `/ipban` and `/ipmute`. |
| `shadow` | `true`: the mute steps are shadow mutes; the muted player's messages are shown to them only. |
| `scope` | Where it applies when the command names no scope: `global`, `server:<name>` or `category:<name>`. Left out: `scopes.default`. A scope given with the command wins. |
| `ladder-expiry` | Earlier punishments older than this don't count (`none` = all count). |
| `address-shared` | `true`: punishments of the player's alts and addresses count too. |
| `permission-required` | `true`: using it needs `sakurabans.template.<name>`. |
| `actions` | Console commands run after every punishment from the template (at most 16, one line each, at most 255 characters). |
| `step-actions` | Console commands for one step only, by step number (from 1). |
| `groups` | `group: weight` (at most 16 groups, weights 1-100). Templates in a group share progress: a punishment from a group mate counts as its weight in that group (voided ones never count). |
| `message` | What the punished player is shown, instead of the network's message for that type (the ban or kick screen, the mute notice in chat, the warning), in MiniMessage with that message's placeholders. One text for every locale. |
| `step-messages` | A message for one step only, by step number (from 1); wins over `message`. |

Names of templates and groups are 1-64 characters of a-z, 0-9, `_` and `-`.

Actions may use `{victim}`, `{uuid}`, `{address}`, `{id}`, `{operator}`, `{reason}`,
`{template}`, `{step}` and `{duration}`. Quote them, because YAML reads `{...}` as a section.

```yaml
templates:
  hacking:
    type: ban
    reason: Unfair advantage (hacked client)
    ladder: [7d, 30d, permanent]
    ladder-expiry: 1y
    address-shared: true
    groups:
      cheating: 2

  spam:
    type: mute
    reason: Spamming
    ladder: [15m, 1h, 1d, 7d]
    ladder-expiry: 30d
    actions: ["say {victim} was muted for {duration}"]

  toxicity:
    type: mute
    reason: Toxic behaviour
    ladder: [kick, 1h, 1d, ban 7d, ban permanent]
    message: "<red>You were muted for toxicity: <reason></red>"
    step-messages:
      4: "<red><bold>Banned for a week.</bold></red><newline><gray><reason></gray>"
```
