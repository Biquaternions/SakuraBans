`import.yml` is read every time an import runs, so edits need no reload. Each import runs once
at a time across the network, and running it again skips what it already imported. The
process is described in [Importing from other plugins](/docs/guides/importing).

Relative paths start at the server folder (the one with `server.properties` or
`velocity.toml`). Imports only read the other plugin's data. Stop the other plugin first, or at
least make sure it doesn't write while the import runs. File databases (H2, HSQLDB) can't be
open in two programs at once.

Each database section has:

| Key | Meaning |
|---|---|
| `jdbc-url` | Where the data is. Empty disables the source. One of `jdbc:mariadb://<host>:<port>/<database>`, `jdbc:mysql://...`, `jdbc:postgresql://...`, `jdbc:h2:<file, without .mv.db>` or `jdbc:hsqldb:file:<file, without .script>`. |
| `username`, `password` | Credentials. |
| `table-prefix` | The prefix the other plugin was set up with (up to 32 characters of A-Z, a-z, 0-9 and `_`; empty for none). |

## Sources

| Section | Notes |
|---|---|
| `self` | Another SakuraBans database, for moving everything (punishments, players, templates, allow list, audit log, ...) to this one, for example from H2 to MariaDB. Only works while this database is still empty, and both must be of the same SakuraBans version. For the default H2 file on Paper: `jdbc:h2:./plugins/SakuraBans/sakurabans` (on Velocity `plugins/sakurabans/`); the server using it must be stopped. |
| `libertybans` | LibertyBans. Its default storage is an HSQLDB file (`plugins/LibertyBans/internal/hypersql/punishments-database`); with MariaDB, MySQL or PostgreSQL use the connection LibertyBans used. Prefix `libertybans_`. |
| `litebans` | LiteBans. Its H2 file is `plugins/LiteBans/litebans.mv.db`. Older LiteBans versions wrote an H2 1.x file, which this H2 can't open: move LiteBans to MySQL or MariaDB first in that case. Prefix `litebans_`. |
| `advancedban` | AdvancedBan. Its default storage is an HSQLDB file (`plugins/AdvancedBan/data/storage`); with MySQL use the connection AdvancedBan used. Its tables have no prefix. |
| `banmanager` | BanManager. Its default storage is an H2 file (`plugins/BanManager/local-bans`); with MariaDB or MySQL use its connection. Prefix `bm_`. |
| `vanilla` | The server's own ban lists, as JSON files: `banned-players` (default `banned-players.json`) and `banned-ips` (default `banned-ips.json`). |
