The editor site is the `web/` folder of the SakuraBans repository: one Nuxt application that
serves the docs, the editor page and a small API that stores encrypted blobs. It never sees
your configuration in readable form.

## With Docker

Build from the **repository root** (the image needs `protocol/` too):

```bash
docker build -f web/Dockerfile -t sakurabans-web .
docker run -d --name sakurabans-web -p 3000:3000 \
  -v sakurabans-editor:/data \
  -e NUXT_EDITOR_UPLOAD_TOKEN=change-me \
  sakurabans-web
```

`web/docker-compose.yml` does the same with a named volume. The container runs the Node server
as an unprivileged user; blobs are stored in `/data`.

Then set `web.url: https://editor.example.org` (and `web.token`, if you set an upload token)
in each server's `config.yml`.

## Without Docker

Node 24 or newer and pnpm:

```bash
cd web
pnpm install
pnpm build
node .output/server/index.mjs
```

## Testing locally

To try the editor against a test server on the same machine:

1. Start the site from `web/`, either the development server or the built one:

   ```bash
   pnpm dev                      # http://127.0.0.1:3000, no security headers
   # or, closer to production:
   pnpm build && HOST=127.0.0.1 node .output/server/index.mjs
   ```

   `pnpm dev` binds to `127.0.0.1` on purpose. Java resolves `localhost` to IPv4 first, and
   some systems run development servers on the IPv6 loopback only, which the plugin then can't
   reach.
2. In the test server's `config.yml`, set `web.url: http://127.0.0.1:3000` (plain `http://` is
   accepted for loopback and private addresses), and leave `web.token` empty unless you set
   `NUXT_EDITOR_UPLOAD_TOKEN`.
3. Run `/sb reload`, then `/sb editor`.
4. The plugin replies with a link to `http://127.0.0.1:3000/editor/<id>#<key>`. Open it: the
   header shows **Connected** once the server has joined the session (with `web.live-apply`
   on), and a save applies within seconds; otherwise you get `/sb applyedits <code>`.

`pnpm dev` doesn't send the security headers (the Content-Security-Policy and the others):
test the built server before you deploy.

## Settings

Every setting is an environment variable (see `web/.env.example`):

| Variable | Default | Meaning |
|---|---|---|
| `PORT`, `HOST` | `3000`, all interfaces | Where the server listens. |
| `NUXT_EDITOR_STORAGE_DRIVER` | `fs` | `fs` (a directory) or `redis`. |
| `NUXT_EDITOR_STORAGE_DIR` | `./.data/editor` (`/data` in Docker) | The directory for `fs`. |
| `NUXT_EDITOR_REDIS_URL` | — | `redis://…` for `redis`. |
| `NUXT_EDITOR_PAYLOAD_TTL` | `86400` | Seconds a snapshot is kept. |
| `NUXT_EDITOR_CHANGES_TTL` | `3600` | Seconds a change set (and its result) is kept. |
| `NUXT_EDITOR_MAX_BLOB_BYTES` | `1048576` | The largest blob accepted. |
| `NUXT_EDITOR_RATE_LIMIT` / `_WINDOW` | `30` / `600` | Uploads per client address per window (seconds). |
| `NUXT_EDITOR_LIVE_RATE_LIMIT` / `_WINDOW` | `120` / `60` | Result requests and socket connections per address per window. |
| `NUXT_EDITOR_TRUST_PROXY` | `false` | Read the client address from `X-Forwarded-For` (the last entry). Only behind a reverse proxy that sets it. |
| `NUXT_EDITOR_UPLOAD_TOKEN` | — | When set, creating sessions needs `Authorization: Bearer <token>`; the plugin sends `web.token`. |
| `NUXT_EDITOR_PURGE_INTERVAL` | `600` | Seconds between sweeps that delete expired blobs. |
| `NUXT_EDITOR_SOCKET_SILENCE` | `60` | Seconds after which a silent live-apply socket is closed. |
| `NUXT_EDITOR_SOCKET_MAX_BROWSERS` | `5` | Browser sockets per session. |
| `NUXT_PUBLIC_PUBLIC_INSTANCE_URL` | — | An instance to name in these docs; empty names none. |

## Storage and expiry

With `fs`, each blob is a small JSON file with its expiry. Expired blobs are refused when read
and deleted by a sweep every `NUXT_EDITOR_PURGE_INTERVAL` seconds. With `redis`, blobs also get
Redis's own expiry. Nothing else is stored: no accounts, no logs of content.

## The upload token

Without a token anyone can create sessions on your site (they are useless without a plugin,
but they use disk). Set `NUXT_EDITOR_UPLOAD_TOKEN` to a long random string and the same value in
`web.token` on your servers. Browsers never need it. Comparison is constant-time.

## One process for live apply

Live apply uses WebSockets, and which sockets are connected to a session is kept **in the
memory of one server process**. Run one process (the default), or make sure all requests for a
session reach the same process. If browser and plugin reach different processes, live apply
doesn't happen, but `/sb applyedits` always works. A restart drops the sockets; both sides
reconnect. The same process also serialises the updates of a session's list of saved changes,
its snapshot revision and its results, so simultaneous saves can't overwrite each other.

## Reverse proxy

Terminate TLS in front of the site, pass WebSocket upgrades for
`/api/sessions/<id>/socket`, keep read timeouts above the 20-second ping, and set
`NUXT_EDITOR_TRUST_PROXY=true` so rate limits see real client addresses.

**nginx:**

```nginx
server {
  listen 443 ssl http2;
  server_name editor.example.org;
  # ssl_certificate ...; ssl_certificate_key ...;

  client_max_body_size 2m;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_read_timeout 120s;
  }
}

# In the http block:
map $http_upgrade $connection_upgrade {
  default upgrade;
  ''      close;
}
```

**Caddy** (WebSockets and `X-Forwarded-For` work out of the box):

```caddyfile
editor.example.org {
  reverse_proxy 127.0.0.1:3000 {
    stream_timeout 24h
  }
}
```

## Security notes

- The site sends a strict Content-Security-Policy (no other origins), `Referrer-Policy:
  no-referrer`, and `Cache-Control: no-store` on the API. Don't add third-party scripts,
  analytics or fonts: the decryption key is in the editor page.
- The server never parses blobs; it checks only their size and first byte.
