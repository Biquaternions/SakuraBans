GeoIP looks up the country of a player's address in a local copy of MaxMind's free
**GeoLite2-Country** database. With it you can:

- turn players away by country when they join (`geoip.blacklist`, `geoip.whitelist`);
- look up a country with [`/geoip <target>`](/docs/commands/alts);
- show the country in staff notices and lookups with the
  [`<country>` tag](/docs/reference/placeholders#countries).

It is **off by default** and costs nothing while off: the reader isn't loaded, no file is read
and no request is made. A ban plugin has little to do with geography (this belongs in an
anti-bot plugin); it is here because LiteBans offers it.

## Setting it up

1. Turn it on in [`config.yml`](/docs/configuration/config#geoip) on each server that should
   check countries: `geoip.enabled: true`. This needs a restart. Each such server keeps its own
   copy of the database in `plugins/SakuraBans/geoip/GeoLite2-Country.mmdb`.
2. Give it the database, one of two ways:
   - **Download it with your MaxMind account.** Sign up for a free GeoLite account at
     [maxmind.com](https://www.maxmind.com/en/geolite2/signup), create a licence key, and set
     `geoip.account-id` and `geoip.license-key` (or the environment variables
     `SAKURABANS_GEOIP_ACCOUNT_ID` and `SAKURABANS_GEOIP_LICENSE_KEY`, see
     [Environment variables](/docs/configuration/environment)). Both are secrets: they never
     reach the log, the database, `/sb settings` or the web editor. The server downloads the
     database at start when it has none.
   - **Place the file by hand.** Leave both empty and put `GeoLite2-Country.mmdb` (from the
     `.tar.gz` MaxMind offers) in the `geoip` folder. It is used as it is; a newer copy put in
     its place is picked up within an hour.
3. Set the lists (below). Until a list is set, GeoIP only answers `/geoip` and `<country>`.

Until a database is loaded, every country is unknown, and `/geoip` says there is no database
yet. A server without a database or account logs one warning.

## Keeping it current

With an account, the server asks MaxMind every `geoip.refresh` (default `7d`, at least `1d`)
whether there is a newer database, and downloads it only then. Asking is free; MaxMind
publishes GeoLite2 twice a week and limits downloads per day. A failed download keeps the old
file and is tried again after 6 hours. `never` downloads only when there is no database.

## Country lists

The lists are **global** settings, set once for the network (in `config.yml`, with
`/sb settings` or the [web editor](/docs/web-editor)); each server with GeoIP on applies them.
Countries are **ISO 3166-1 alpha-2 codes**, such as `US`, `DE` or `GB` (not `UK`): see the
[list of codes](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2#Officially_assigned_code_elements).
An unknown code is a configuration error.

```yaml
geoip:
  enabled: true
  blacklist: [CN, RU]
```

When a player joins, after the ban check:

1. A player or an address on the **allow list** (`/sb allow add`, see
   [Administration](/docs/commands/administration#allow-list)) gets in.
2. A player with **`sakurabans.geoip.bypass`** gets in (see the limit below).
3. A country that isn't known (a local or private address, as on a LAN, an address the database
   doesn't list, or no database yet) gets in when `geoip.allow-unknown` is `true` (the default),
   and is turned away when it is `false`.
4. With a non-empty **`geoip.whitelist`**, only its countries get in. The whitelist wins: with
   both lists set, the blacklist is ignored and the configuration warns.
5. Otherwise the countries of **`geoip.blacklist`** are turned away.

A player turned away sees `screen.geoip`, and staff with `sakurabans.notify.attempt.join` are
told (`notify.attempt_geoip`); a country that isn't known shows as `unknown`
(`geoip.unknown_country`) in both. The notice uses the same throttle as the "tried to join while banned" notice
(`notifications.attempt-throttle`). It is **not a punishment**: nothing is stored or audited, no
webhook is posted, and it doesn't count anywhere. Plugins see it as a `PlayerDenyEvent` with
`LOGIN_GEOIP_BLOCKED` and can let the player in by cancelling it.

A banned player sees the ban first: the country is only checked for players the ban check
lets in.

### The bypass permission

At login the player isn't on the server yet, so their permissions are only known through
**LuckPerms**, which SakuraBans asks (as for `sakurabans.lockdown.bypass`), on Paper and on
Velocity. Without LuckPerms nobody has the bypass at login. **Prefer the allow list** for
players who must always get in: it works everywhere and also lets their address through.

## Proxies and backends

GeoIP is a login decision. Install SakuraBans on the proxy, and the country is checked when a
player connects to the proxy; switching servers is never checked. Install it on the backends,
and each backend with GeoIP on checks the players joining it.

Servers that let banned players in
([`enforcement.servers-without-login-check`](/docs/configuration/config#enforcement) on a
proxy, `enforcement.login-check: false` on a backend) **still check countries**: they skip the
ban check, not GeoIP.

## Privacy

Lookups are made **in memory**, from the local file: no player address ever leaves the server.
The only request goes to MaxMind, to download the database with your account, with a generic
user agent and nothing about the server or its players. `<country>` is deliberately not offered
to MiniPlaceholders or PlaceholderAPI.
