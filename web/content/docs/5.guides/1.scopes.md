Every punishment has a **scope**: where it applies.

| Scope | Written as | Applies |
|---|---|---|
| Global | `global` | Everywhere. |
| Server | `server:<name>` | On the server whose `server.name` (on a backend) or proxy server name (on a proxy) is `<name>`. |
| Category | `category:<name>` | On every server in the category. |
| Local | `local` | Only as input: this server (global while `server.name` is empty); on a proxy, the server the staff member is on. |

## Choosing the scope

1. A scope given with the command wins: `-g`, `--server <name>`, `--category <name>` or
   `--scope <scope>`.
2. Otherwise the template's `scope`, if a template is used.
3. Otherwise `scopes.default` of the server where the command runs.

Revocations take `--scope <scope>` or `--scope all`; without it they revoke in every scope.

## Categories

A category is a named group of servers. Define them once in `scopes.categories`:

```yaml
scopes:
  categories:
    minigames: [bedwars-1, bedwars-2, skywars]
    survival: [survival, survival-nether]
```

Alternatively a backend can list its own categories in `server.categories`. On a network of
backends, `scopes.categories` must be the same everywhere: each server only knows the
categories in its own file. A database override (set in the [web editor](/docs/web-editor))
solves that for the whole network at once.

## Permissions

With `scopes.require-permissions: true`, staff need `sakurabans.scope.global`,
`sakurabans.scope.server.<name>` or `sakurabans.scope.category.<name>` to punish or revoke in a
scope, and `sakurabans.scope.default` to punish without naming one.

## Scopes and templates

A template has two scopes that mean different things. Its `scope` key is where its punishments
apply (like `--server` on the command). Its **variants** are definitions in force for a server
or a category instead of the global one: which one a use gets depends on where it is issued or
the scope the command names, in the same order as settings (the server, its categories, then
global). See [Variants](/docs/guides/templates#variants).

## Where scopes are checked

- **On backends**, each server enforces the punishments of its own scopes: global ones, those
  for its `server.name`, and those of its categories. A backend without a name only sees global
  ones and its `server.categories`; it warns at startup if scopes are in use.
- **On a proxy**, server and category punishments follow the player as they switch servers
  (`enforcement.enforce-server-switch`), for bans and mutes.
