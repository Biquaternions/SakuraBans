A **template** is a named punishment rule, such as `hacking` or `spam`. Staff use it with
`--template` (or `-t`):

```
/ban Steve --template hacking
/ban Steve -t hacking -r caught on camera
```

The template decides the type, the duration and the default reason; a reason given with `-r`
replaces the template's. Tab completion lists the templates. The keys are listed in
[templates.yml](/docs/configuration/templates).

## Ladders

A ladder is one duration per step. The first punishment from a template uses the first step,
the next one the second, and so on; after the last step the last one repeats.

```yaml
hacking:
  type: ban
  reason: Unfair advantage (hacked client)
  ladder: [7d, 30d, permanent]
  ladder-expiry: 1y
```

Here the first ban lasts 7 days, the second 30 days, and every later one is permanent.
`ladder-expiry: 1y` means earlier punishments older than a year don't count, so the ladder
starts over for a player who behaved for a year.

- `address-shared: true` counts punishments of the player's alts and addresses too.
- Voided punishments never count.
- `step-actions` run console commands at one step only; `actions` run after every punishment.

## Mixed ladders

A step may name its own type, so one template can escalate from kicks to mutes to bans:

```yaml
toxicity:
  type: mute
  reason: Toxic behaviour
  ladder: [kick, 1h, 1d, ban 7d, ban permanent]
```

The first time a player gets `toxicity` they are kicked, then muted for an hour, then for a day,
then banned for a week, then permanently. Steps without a type (`1h`, `1d`) use the template's
`type`. The ladder counts every punishment from the template (and its group mates), whatever its
type.

- `--template` is offered on the command of the template's type, and on every punish command
  when the ladder is mixed.
- The sender needs the permission of the type the step results in (and
  `sakurabans.template.<name>` when the template requires it); limits, cooldowns and exemption
  apply to that type.
- `shadow` applies to the mute steps; `ip` to every step.

## Messages

A template can carry what the punished player sees, instead of the network's message for that
type: `message` for every step, `step-messages` for single steps (a step message wins). Without
either, the network's message applies. They use the placeholders of the network's message for
that type (the ban and kick screens, the mute notice, the warning) and are one text for every
locale.

```yaml
hacking:
  type: ban
  reason: Unfair advantage (hacked client)
  ladder: [7d, 30d, permanent]
  message: "<red>Banned for cheating.</red><newline><gray>Appeal at example.org/appeal</gray>"
  step-messages:
    3: "<red>Permanently banned for cheating.</red>"
```

The message is read from the template when it is shown, so editing it changes what players
already banned see on their next attempt to join; if the template is deleted, the network's
message applies again.

## Groups

Templates in a **group** share progress. A punishment from a group mate counts as its weight
in that group:

```yaml
hacking:
  ladder: [7d, 30d, permanent]
  groups: {cheating: 2}
xray:
  ladder: [3d, 14d, permanent]
  groups: {cheating: 1}
```

An x-ray ban counts as one step towards `hacking`, a hacking ban as two towards `xray`. A
template in no group counts only towards itself, which suits bans for one game mode.

## Where templates live

Templates are stored in the database and shared by every server on it. `templates.yml` seeds
them on the first start; afterwards use `/sb templates import|export`, the API, or the
[web editor](/docs/web-editor), which also imports and exports `templates.yml` files in the
browser.

## Permissions and limits

- `permission-required: true` makes a template need `sakurabans.template.<name>`.
- `require-template` in [limits.yml](/docs/configuration/limits) can make templates
  mandatory for a staff group.
