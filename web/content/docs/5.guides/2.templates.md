A **template** is a named punishment rule, such as `hacking` or `spam`. There are two kinds:

- a **preset** fills in one punishment: its type, reason, duration, message and actions;
- a **ladder** escalates: each time it is applied to a player it goes one step further, and
  every step decides its own punishment (or none).

The keys are listed in [templates.yml](/docs/configuration/templates).

## Presets

A preset has the type of the command it is used with (`type: ban`, `mute`, `warn` or `kick`).
Staff use it with `--template` (or `-t`):

```
/ban Steve -t hacking
/mute Steve -t spam -r flooding the chat
```

```yaml
hacking:
  type: ban
  reason: Unfair advantage (hacked client)
  duration: 30d
```

- `-t` is offered and accepted only on the command of the preset's type: a mute preset on
  `/mute`, `/tempmute` and `/ipmute`, not on `/ban`.
- `duration` fixes how long: then the command refuses `-d`, and the preset isn't offered on
  `/tempban` or `/tempmute`. Left out, the command decides (`-d`, the temp command's duration,
  else permanent; a warning gets `warnings.expire-after`). `duration: permanent` is always
  permanent.
- A reason given with `-r` replaces the template's.

## Ladders

A ladder (`type: ladder`) is a list of steps. The first time it is applied to a player the
first step is used, the next time the second, and so on; after the last step the last one
repeats. Each step names its own type:

```yaml
misconduct:
  type: ladder
  reason: Repeated misconduct
  steps:
    - warn
    - kick
    - mute 1d
    - {step: none, actions: ["say {victim} is on a final warning"]}
    - ban 7d
    - ban permanent
  expiry: 90d
```

A player who misbehaves is warned, then kicked, then muted for a day; the fourth time nothing
happens to them, but the staff are told; then they are banned for a week, then for good.

Ladders are applied with `/punish`:

```
/punish Steve misconduct
/punish Steve misconduct -s -r spamming in chat
```

- `/punish` needs `sakurabans.punish` (and `sakurabans.template.<name>` when the ladder has
  `permission-required: true`), not the permission of the type the step results in. Its flags
  need `sakurabans.punish.<flag>`.
- The step decides the type and the duration. `limits.yml` doesn't cut a step's duration;
  cooldowns and exemption apply by the step's type.
- A **`none`** step punishes nothing: only its actions run (it needs at least one, and has no
  message). It still counts as a use, so the next use goes on to the next step.
- A step can have its own `reason` and `message` (they win over the template's) and `actions`
  (run after the template's).
- `expiry: 90d`: earlier uses older than 90 days don't count, so the ladder starts over for a
  player who behaved for that long. `address-shared: true` counts uses on the player's alts and
  addresses too. Uses whose punishment was voided never count.
- `/sb templates reset <player|address> [template]` makes the ladders start over for a player
  or an address. It deletes what each ladder counts for the target: the uses of the ladder and
  its group mates, on the target's alts and addresses too when the ladder is `address-shared`
  (so their ladder starts over as well). Naming a preset deletes only the target's own uses of
  it. The confirmation says how many uses of how many victims go.
- Two `/punish` on one player at the same moment get consecutive steps. With
  `address-shared`, two applies on different accounts of the same person at the same moment
  can still get the same step.

## Messages

A template can carry what the punished player sees, instead of the network's message for that
type: `message` on the template, and on a ladder also `message` on a single step (which wins).
Without either, the network's message applies. They use the placeholders of the network's
message for that type (the ban and kick screens, the mute notice, the warning) and are one text
for every locale.

```yaml
hacking:
  type: ban
  reason: Unfair advantage (hacked client)
  duration: 30d
  message: "<red>Banned for cheating.</red><newline><gray>Appeal at example.org/appeal</gray>"
```

The message is read from the template when it is shown, so editing it changes what players
already banned see on their next attempt to join; if the template is deleted, the network's
message applies again.

A mute or warning can also be shown as a dialog instead of a chat line, with `display: dialog`
on a mute or warn preset or a ladder (it then covers the ladder's mute and warn steps). Paper
always shows it; a Velocity proxy needs the packetevents plugin, and players on clients older
than 1.21.6 get the chat line. See
[Dialogs](/docs/configuration/templates#dialogs).

## Groups

Templates in a **group** share progress. Every use of a group mate counts as its weight on the
ladders of that group, presets included:

```yaml
cheating:
  type: ladder
  reason: Cheating
  steps: [ban 7d, ban 30d, ban permanent]
  groups: {cheating: 2}
xray:
  type: ban
  reason: X-ray
  duration: 3d
  groups: {cheating: 1}
```

An `xray` ban (a preset) counts as one step towards the `cheating` ladder, and each use of the
ladder as two. A template in no group counts only towards itself, which suits bans for one game
mode.

## Variants

A template's name is one identity across the network, but its definition can differ per server
or category. Say `spam` mutes for an hour, but Skywars wants a day and a message of its own:
open the Templates tab of the [web editor](/docs/web-editor), switch "Definitions for" to
`server:skywars`, and **Create variant from global**; or add it to `templates.yml` under
`variants` and run `/sb templates import server:skywars`.

- `/mute Steve -t spam` run on the Skywars backend (or, on a proxy, by staff standing on
  Skywars) uses the Skywars variant; anywhere else, the global definition.
- A server without a variant of its own uses its categories' (the first in
  `scopes.categories` that has one), then the global definition.
- `/mute Steve -t spam --server skywars` uses the Skywars variant from anywhere; `-g` uses the
  global one. The command's scope picks both where the punishment applies and which
  definition is used.
- The variant is the same kind of template as the global one and has no groups of its own;
  progress on a ladder is shared by name, so a player's third use is the third step whichever
  server the first two were on.
- A ban issued from a variant shows that variant's screen on every server, even a global ban
  enforced on another backend.

`/sb templates list server:skywars` lists the variants of a scope; `/sb templates list` shows
which scopes each template has variants in.

## Where templates live

Templates are stored in the database and shared by every server on it. `templates.yml` seeds
them on the first start; afterwards use `/sb templates import|export [scope]` (`--all` for
every section), the API, or the [web editor](/docs/web-editor), which also imports and exports
`templates.yml` files in the browser, variants included.

## Permissions and limits

- `permission-required: true` makes a template need `sakurabans.template.<name>`, for a ladder
  and for a preset, whether it is used by a command or through the API; the node is the
  template's name, whichever variant is in force. Its punishments need the node too, to be
  revoked, edited, voided, deleted or overridden (the console always may), until the template
  is deleted.
- `silent: true` makes its punishments silent, as if `-s` had been given; `--hide` and
  `--quiet` still hide them further.
- `require-template` in [limits.yml](/docs/configuration/limits) can make templates
  mandatory for a staff group.
