SakuraBans keeps a few numbers in memory so messages, scoreboards and tab lists can show them
without ever waiting for the database (as LiteBans' FAQ puts it, a placeholder must never run a
query): the **network's counts**, read again every
[`placeholders.refresh`](/docs/configuration/config#placeholders) (default `2m`), and **each
online player's own counts**, read when they join and whenever one of their punishments is
issued, revoked, voided, deleted, edited or expires, on this server or through sync. A value
that isn't known yet (just after a start, or a player whose counts are still loading) is
**empty**, not `0`.

What counts:

- **Totals** are every stored punishment of the type that wasn't voided, revoked and expired
  ones included (hidden and quiet ones too; a kick with `--no-record` isn't stored). **Active**
  ones are those in force now.
- **A player's counts** are the punishments with their UUID as the victim (alone or with an
  address) in **every scope**, voided ones left out. A punishment of an address alone doesn't
  count for anyone.

## In messages

These MiniMessage tags work in [language files](/docs/configuration/languages), message
overrides and templates' messages. None of the shipped texts use them.

| Tag | Where | Value |
|---|---|---|
| `<total_bans>` `<total_mutes>` `<total_warns>` `<total_kicks>` | every message | the network's totals |
| `<active_bans>` `<active_mutes>` `<active_warns>` | every message | in force now |
| `<player_bans>` `<player_mutes>` `<player_warns>` `<player_kicks>` | messages that show a punishment | what its victim received |
| `<player_active_warns>` | messages that show a punishment | the victim's warnings in force |

The `<player_*>` tags are for the punishment's victim, in the screens and notices the punished
player gets (`screen.*`, `victim.*`, `dialog.*`, `chat.*`), the staff notices (`notify.*`) and
the command replies that show a punishment (`check.detail`, `list.entry`, the replies of the
punishment, void and delete commands). The web editor lists them for those messages.

- A victim online on this server: from memory.
- A victim who isn't: the staff notices, `/check #<id>` and `/sb info` read their counts first,
  but only when the message's text (in any language or override) uses one of these tags, so
  nothing changes while no text does. Elsewhere the tags are empty for them.
- A ban screen at login shows the counts if they were read by the time the screen is built;
  they are read alongside the login check, which never waits for them.
- An address victim: empty.
- What the punished player is shown never counts **shadow mutes** in `<player_mutes>`; staff
  messages do.

## Countries

With [GeoIP](/docs/guides/geoip) on, `<country>` is the English name of the country of an
address (for example `United Kingdom`). It is empty while GeoIP is off on the server or the
country isn't known (a private address, one the database doesn't list, or no database yet),
except in the GeoIP screen and notice (`screen.geoip`, `notify.attempt_geoip`), which show the
text of `geoip.unknown_country` (`unknown`) instead. It works only in messages that already
have the address:

| Message | Address |
|---|---|
| `notify.attempt_join`, `notify.alts.join` | the joining player's |
| `alts.entry` | the addresses the alt shares (each country once, comma-separated) |
| `iphistory.entry` | that address |
| `check.detail` (`/check #<id>`, `/sb info`) | an address punishment's; empty for a player's |
| `screen.geoip`, `notify.attempt_geoip`, `geoip.result` | the GeoIP texts, which use it |

The web editor lists it for exactly those messages. Only the GeoIP texts use it as shipped.
It is not a MiniPlaceholders or PlaceholderAPI placeholder: a player's country isn't something
to hand to every plugin.

## MiniPlaceholders and PlaceholderAPI

With [MiniPlaceholders](https://modrinth.com/plugin/miniplaceholders) (Paper or Velocity) or
[PlaceholderAPI](https://modrinth.com/plugin/placeholderapi) (Paper) installed, SakuraBans
registers the expansion `sakurabans`. In MiniPlaceholders a placeholder is the tag
`<sakurabans_name>`, in PlaceholderAPI `%sakurabans_name%`. The same names work in both:

| Name | Needs a player | Value |
|---|---|---|
| `sakurabans_muted` | yes | `true` or `false` (empty until the player's mutes are loaded) |
| `sakurabans_mute_reason` | yes | the reason of the mute in force, else empty |
| `sakurabans_mute_remaining` | yes | how long it still runs (`time.permanent` for a permanent one), else empty |
| `sakurabans_mute_expires` | yes | when it ends (`time.never` for a permanent one), else empty |
| `sakurabans_player_bans` | yes | bans the player received |
| `sakurabans_player_mutes` | yes | mutes the player received, shadow mutes left out |
| `sakurabans_player_warns` | yes | warnings the player received |
| `sakurabans_player_kicks` | yes | kicks the player received |
| `sakurabans_player_active_warns` | yes | the player's warnings in force |
| `sakurabans_total_bans` | no | the network's bans |
| `sakurabans_total_mutes` | no | the network's mutes |
| `sakurabans_total_warns` | no | the network's warnings |
| `sakurabans_total_kicks` | no | the network's kicks |
| `sakurabans_active_bans` | no | bans in force |
| `sakurabans_active_mutes` | no | mutes in force |
| `sakurabans_active_warns` | no | warnings in force |

- The player is the one the placeholder is evaluated for. Their mute is the one that applies
  where they are now (on a proxy: the server they are on), as when they chat.
- **A shadow mute is never revealed** by a placeholder, to anyone: a placeholder's value is
  often shown to others (tab list, name tags) and always to the player, so a shadow-muted
  player reads as not muted and the mute isn't in `sakurabans_player_mutes`. Use `/check`.
- Values are text: a mute reason is never parsed as tags.
- Values are read from memory, so PlaceholderAPI may ask on any thread, Folia regions included.
- Neither plugin is required. When one isn't installed, SakuraBans loads nothing of it. When the
  installed version doesn't fit, one warning says so and the placeholders stay off; the rest of
  SakuraBans works as before. MiniPlaceholders 3.2.0 (the release when this was written) was
  built for Paper up to 26.2, Velocity 3 and Adventure 4; SakuraBans' bridge only uses parts of
  its API that exist unchanged in Adventure 5.2, but it hasn't been tried on a server.
