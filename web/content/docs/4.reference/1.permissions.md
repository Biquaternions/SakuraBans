`<type>` is one of `ban`, `mute`, `warn` and `kick`.

A player acting in game is checked with their permissions on the server. When an action is
made on behalf of a player who isn't online (another plugin calling the API with that player as
the actor), SakuraBans asks LuckPerms for that player's permissions; without LuckPerms, such an
action is refused. The console, and plugins acting under their own name, are not checked.

## Per punishment type

| Node | Grants |
|---|---|
| `sakurabans.<type>` | Issue it (`/ban`, `/mute`, `/warn`, `/kick`, `/ipban`, `/ipmute`, and the temp commands). |
| `sakurabans.<type>.temporary` | Only the temp command (`/tempban`, `/tempmute`). |
| `sakurabans.<type>.silent` | The `--silent` flag (punish and revoke). |
| `sakurabans.<type>.hide` | The `--hide` flag (punish and revoke). |
| `sakurabans.<type>.ip` | Punish addresses: `--ip`, address targets, `/ipban`-style punishments. |
| `sakurabans.<type>.range` | Punish address ranges. |
| `sakurabans.mute.shadow` | The `--shadow` flag. |
| `sakurabans.<type>.override` | `--override` and `--if-longer`. |
| `sakurabans.<type>.skip` | The `--skip` flag. |
| `sakurabans.<type>.evidence` | The `--evidence` flag. |
| `sakurabans.<type>.revoke` | Revoke any punishment of the type. |
| `sakurabans.<type>.revoke.own` | Revoke the ones you issued. |
| `sakurabans.<type>.void` | Void instead of revoking (`--void`). |
| `sakurabans.<type>.edit` | `/sb edit` and `/sb evidence` on any punishment of the type. |
| `sakurabans.<type>.edit.own` | The same on your own. |
| `sakurabans.<type>.delete` | `/sb delete`. |
| `sakurabans.<type>.check` | `/checkban`, `/checkmute`, `/checkwarn`. |
| `sakurabans.<type>.notify` | Hear about new punishments. |
| `sakurabans.<type>.notify.silent` | Hear about silent ones too. |
| `sakurabans.<type>.notify.revoke` | Hear about revocations. |
| `sakurabans.<type>.exempt` | Can't be punished (with `exemption.provider: PERMISSION`). |
| `sakurabans.<type>.exempt.bypass` | Punish exempt players. |

## Scopes

Checked only with `scopes.require-permissions: true`.

| Node | Grants |
|---|---|
| `sakurabans.scope.global` | Punish and revoke globally. |
| `sakurabans.scope.server.<name>` | On that server. |
| `sakurabans.scope.category.<name>` | In that category. |
| `sakurabans.scope.default` | Punish without naming a scope. |

## Templates and limits

| Node | Grants |
|---|---|
| `sakurabans.punish` | `/punish`: apply a ladder, whatever type its step results in. |
| `sakurabans.punish.<flag>` | A flag of `/punish`: `silent`, `hide`, `skip`, `evidence`, `ip`, `range`, `override`. |
| `sakurabans.template.<name>` | Use a template (preset or ladder) with `permission-required: true`, from a command or through the API (`PunishmentService.punish` and `applyLadder` check it too). The name is the template's, whichever variant is used. |
| `sakurabans.limits.unlimited` | Ignore `max-duration` and `require-template` of `limits.yml`. |
| `sakurabans.cooldown.bypass` | Ignore cooldowns. |

Staff groups of `limits.yml` use permissions you choose (for example `sakurabans.group.helper`).

## Web editor

| Node | Grants |
|---|---|
| `sakurabans.editor` | `/sb editor` and `/sb applyedits`. |

Each section of the editor needs the same node as its in-game administration:
`sakurabans.admin.settings` (Settings), `sakurabans.admin.messages` (Messages) and
`sakurabans.admin.templates` (Templates). A section you may not change isn't sent to the
editor, and a change set that touches one is refused as a whole.
